# البنية التقنية

## الطبقات

| الطبقة | الموقع | المسؤولية |
|---|---|---|
| البيانات | `data/Entities.kt`, `data/Daos.kt`, `data/AppDatabase.kt` | Room، الكيانات، الاستعلامات |

## تدفق البيع

1. `PosScreen` يضيف المنتجات إلى `cart` مع السعر حسب فئة السعر.
2. `AppViewModel.checkout` يبني `InvoiceRequest`.
3. `Repository.createInvoice` داخل `db.withTransaction`:
   - يحسب `subtotal` ثم `discount` ثم `tax` ثم `total`.
   - يحسب `paid` و`remaining` وحالة السداد.
   - ينشئ رأس الفاتورة وأصنافها.
   - يحدّث مخزون المستودع ويسجّل `stock_moves`.
   - يحدّث رصيد العميل/المورد بالباقي فقط.
   - يسجّل الدفعة الأولى إن وجدت.
   - ينشئ جدول الأقساط عند البيع بالتقسيط.
4. تُعرض نافذة طباعة، ويمكن معاينة الفاتورة قبل الطباعة.

## معادلات المال

```
lineTotal = round(qty * unitPrice - lineDiscount)
subtotal  = Σ lineTotal
taxable   = subtotal - invoiceDiscount
tax       = round(taxable * taxRate / 100)
total     = round(taxable + tax)
remaining = total - paid
profit    = Σ(lineTotal - costPrice * qty)
```

كل المبالغ تُقرّب لخانتين عبر `Money.round` لتجنب أخطاء الفاصلة العائمة.

## المخزون

- `stock` صف فريد لكل (مستودع، منتج).
- كل تغيير يُسجّل في `stock_moves` مع السبب (`SALE`, `PURCHASE`, `ADJUST`, `TRANSFER_IN`, ...).
- البيع والمرتجع الشرائي ينقصان، الشراء والمرتجع البيعي يزيدان.
- نقل المخزون يخصم من مستودع ويضيف للآخر في معاملة واحدة.

## الأرصدة

`customers.balance` و`suppliers.balance` تمثل صافي المستحق:
- بيع بباقٍ → زيادة رصيد العميل.
- تحصيل → تخفيض رصيد العميل.
- شراء بباقٍ → زيادة رصيد المورد.
- دفع للمورد أو مرتجع → تخفيض الرصيد.

تبقى تفاصيل كل فاتورة محفوظة (`paid`, `remaining`) وتُستخدم في التقارير وكشوف الحساب.

## تعدد المشاريع

كل جدول تشغيلي يحمل `projectId`. الاستعلامات كلها مقيّدة بالمشروع النشط، ما يضمن عزلاً كاملاً للبيانات بين الأنشطة التجارية. الفروع والمستودعات مرتبطة بالمشروع، والجلسة تحفظ المشروع/الفرع/المستودع النشط.

## الطباعة

- خيار 1: بلوتوث SPP → تُرسم الفاتورة كصورة نقطية بدقة 384/576 بكسل وتُرسل كأمر `GS v 0`، فتُطبع العربية بشكل صحيح على معظم الطابعات الحرارية.
- خيار 2: بدون عنوان MAC → `Android Print Framework` يرسم الفاتورة في PDF ويُرسلها لطابعة النظام أو «حفظ كـ PDF».

## الأمان

- كلمات المرور: SHA-256 مع ملح عشوائي 16 بايت و12,000 تكرار.
- الجلسة في `SharedPreferences` محلية.
- لا اتصالات شبكة، لا تحليلات، ولا رفع بيانات.
